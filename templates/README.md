# templates/ — printable paper artifacts

**Nothing in here is part of the running application.** No file in `src/` or `server/`
imports anything from this folder. It is not a route, not a component, and not bundled by
Vite. These are static documents meant to be opened in a browser and printed.

## `pm-checksheet-print.html`

A paper mirror of the digital Checksheet form — 4 pages, one per machine, A4 portrait.
Printed and photographed, it becomes the input artifact for the camera-scan feature.

### Printing

Open in a browser → `Ctrl+P`, then:

| Setting | Value | Why |
|---|---|---|
| Scale | **100%** | "Fit to page" shrinks the checkboxes below a reliable scan size |
| Margins | **Default** | The layout already reserves an 11mm/10mm safe area |
| Background graphics | **ON** | Header bands and table shading are structural, not decoration |
| Paper | **A4 portrait** | `@page` is sized for A4; US Letter will clip the footer |

The on-screen blue banner is `@media print`-hidden and will not appear on paper.

### Where the content comes from

Every machine, inspection point, hint, and finding category is transcribed from the app's
own source of truth:

| Content | Source |
|---|---|
| Machines + per-machine checklists | `server/src/seed.ts` → `machineDefs` |
| Finding categories (6) | `src/data.js` → `FINDING_CATEGORIES` |
| Starred (`*`) categories | `src/data.js` → `PART_REQUEST_CATEGORIES` |
| Which fields are captured | `server/src/routes/checksheets.ts` → `bodySchema` |
| Technician roster | `server/src/seed.ts` → `techs` |

**This is a snapshot, not a live binding.** Editing a checklist item in `seed.ts` does not
update this file. Re-verify after any change to the lists above.

### Two deliberate deviations, both marked on the page

1. **Shift selector** — has no counterpart in the digital form, which only auto-stamps
   `submitted_at`. Labelled *"paper only"* on every page so a later scan pass doesn't hunt
   for a column with no home in the schema.
2. **"Photo attached" per row** — maps to the *per-checkpoint evidence photo*
   (`CheckpointPhoto` in `src/screens/Checksheet.jsx`), the one the vision model actually
   sees. It is **not** the general "Photo evidence" card lower in that screen, which is
   still mocked metadata and explicitly not AI-checked.

### Fields the system generates

The grey "Generated by SmartPM on entry" strip above the signature block lists fields that
are derived server-side and must never be hand-written: checksheet code, work order code,
sheet status, per-finding severity, and the submitted timestamp.
