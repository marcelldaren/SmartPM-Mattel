# Deploying SmartPM to Render (free)

Two free services, no Docker, no Ollama. Roughly 20 minutes, most of it waiting for builds.

| Service | What it runs |
|---|---|
| `smartpm` | Node — the API **and** the built React UI, on one origin |
| `smartpm-ai` | Python — embeddings, drafting, search synthesis, scan (Gemini) |

Ollama is local-development-only and is never deployed. Every AI feature falls back to
deterministic output if the AI service is unreachable, so the app degrades rather than breaks.

## 1. Push the repo

```bash
cd C:/Users/ASUS/Downloads/Github/SmartPM-Mattel
git push -u origin main
```

A browser or credential prompt may appear the first time — that's GitHub asking you to sign in.

## 2. Create the services

1. Go to **dashboard.render.com** → **New** → **Blueprint**.
2. Pick the `SmartPM-Mattel` repository. Render reads `render.yaml` and proposes both services.
3. Click **Apply**. It will prompt for the values marked `sync: false` — see the next section.

## 3. Environment variables to enter

Render asks for these on first deploy and stores them encrypted. **None of them are in the
repository**, which is the point — the API key and mail credentials never touch GitHub.

**On `smartpm-ai`:**

| Key | Value |
|---|---|
| `GEMINI_API_KEY` | your Gemini key |

**On `smartpm`:**

| Key | Value |
|---|---|
| `DEMO_VENDOR_EMAIL` | the inbox that should receive demo vendor mail |
| `SMTP_USER` | your Gmail address — *leave blank to disable real sending* |
| `SMTP_PASS` | your 16-character Gmail App Password |
| `SMTP_FROM` | same as `SMTP_USER` |

`JWT_SECRET` is generated by Render automatically. Don't set it by hand.

### About email

Leaving `SMTP_USER` and `SMTP_PASS` blank is a valid choice: `sendMail` returns false, the
request status still flips to "sent", and the flow demos identically with nothing leaving the
server. Fill them in only if you want a real message to arrive during the presentation.

`DEMO_VENDOR_EMAIL` overrides the recipient on **every** outgoing message. The shipped demo
database has placeholder `.example` vendor addresses that can never deliver, so without this
variable no vendor mail reaches a real inbox.

## 4. Change the demo password

The repo documents `supervisor` / `smartpm123`. On a public URL that is a login anyone can use,
and with SMTP enabled they could send mail from your account. Log in once after deploy and
change it, then text the new password to whoever is presenting.

## Presentation-day checklist

**Free instances sleep when idle, and waking takes tens of seconds.**

1. **Ten minutes before presenting**, open the app URL and log in. This wakes the Node service.
2. **Run one AI Search.** This wakes the Python service, which sleeps separately. Skipping this
   means the first AI feature shown on stage waits ~30–60s or falls back to template output.
3. Confirm the dashboard shows checksheets. If it's empty, the service restarted mid-wake —
   reload once.

That's it. Two page loads, done well before anyone is watching.

## If something goes wrong on the day

| Symptom | Cause | Fix |
|---|---|---|
| Page won't load, spinner forever | Node service asleep | Wait ~60s, reload |
| AI Search returns generic text | Python service asleep | Run the search again |
| `502` on login | Node service still booting | Wait 30s, reload |
| Email doesn't arrive | `SMTP_*` unset, or Gmail rejected the login | Expected if SMTP is off — the demo still works |

**Have a recorded video on the laptop.** Venue wifi, a Gemini rate limit, or a bad morning at
Render all end the same way without one. It costs twenty minutes to record and it is the only
fallback that depends on nothing.

---

## Restarting resets the data

Render's free tier has an ephemeral filesystem. On restart the database reverts to
`deploy/smartpm.demo.db` as committed. That is deliberate — every restart gives a clean, full
demo instead of an empty dashboard or a queue someone already clicked through. Anything
submitted during a demo disappears on the next restart.

To change what the demo starts with, regenerate that file locally and commit it.
